完成形の計画の全体像

GitStation（社内 Git 基盤）・Kanflow（社内 PM ツール）・エージェントモデル（Claude Code の設定）
複数人のバイブコーディングで、速く、壊れにくく開発するための仕組み

2026-10-31 時点　／　出典: GitStation docs/plan/01〜07、ADR、引き継ぎメモ

1. 目的と完成形の要点

社内で閉じた（オンプレの）環境で、複数の開発者と複数の AI セッションが同時に、PBI から本番デプロイまでを速く、安全に進められるようにする。

柱完成形でできること
計画から実装までClaude Code が Kanflow の PBI・受入基準を読み、タスクに分け、作業を宣言し、並行して実装する
実装からマージまでGitStation に PBI 番号付きのブランチを push → パイプライン → MR → マージキュー → 条件付きの自動マージ
マージから本番まで人の承認で社内サーバーに本番デプロイ → Kanflow のリリースとリリースノートに反映
品質と安全エラーの契約、権限の一点の判断、独立レビュー、危険の検査（個人情報の流出や DB の破壊は自動マージしない）
学習と再発防止失敗と直し方を Kanflow にチームで集め、再発したら仕組み（ゲート・テスト・規則）に変える
「完全無敵」の定義: どれか 1 つの仕組みが外れても、ほかの仕組みが止める（多層の防御）。壊れたら数分で気づき、記録から原因が分かる。失敗はゼロにできないので、§10 の数値で測る。

3. 開発の流れ（PBI から本番まで）

図 2　PBI から本番までの流れ。人が判断するのは 4 か所だけ（丸印）。

自動マージの方式（プロジェクトごとに選ぶ）

方式動き人の関与
off自動マージしない毎回
reserve（既定）人が「承認してマージを予約」すると、CI が緑になった時点でマージ予約の 1 回
conditional共通の条件 + AI の仕様照合の承認で自動。認証・DB のマイグレーションなど保護するパスは人を待つ保護するパスだけ
full共通の条件 + AI の承認で、パスの例外なく自動なし

共通の条件: マージキューで、先に並ぶ MR を含めたマージ結果のパイプラインが緑。必須チェックがすべて緑。個人情報・機密の流出や DB の破壊の危険（stop）は、どの方式でも止めて人の承認を待つ。マージするのは GitStation の「自動マージ」の主体で、AI のトークン自身にはマージの権限を与えない。

5. 品質と安全の仕組み（多層の防御）

層仕組み状態
エラーの契約すべての失敗に番号 FG-<領域>-<番号>（原因・診断・直し方・手順書・テスト）。ログには request_id と error_code。利用者には user_message と request_id だけGitStation で稼働
権限判断は forge_auth::authorize() の 1 か所。すべてのルートと git の操作が許可・拒否の両方の行を持つ表に載る。証明（Authorized）がないとハンドラに届かないGitStation で稼働
失敗の握りつぶしの禁止Result を捨てない、unwrap / panic を本番の経路に置かない、外部の呼び出しには必ずタイムアウト規則とレビュー
存在の漏れの防止無いパス・削除済み・見えないパスは同じ応答。DB の問い合わせも同じ形phase 8 で実装
独立レビュー作った AI と評価する AI を分ける。言語・セキュリティ・DB・権限・git の評価役。見逃しは eval にする運用中
ゲート（機械の検査）fmt・clippy・テスト・エラーの目録・権限の表・生成物・i18n を AI のレビューより先に一部。CI は W2
マージの安全マージキュー、危険の検査（stop）、本番は人の承認、main が壊れたら原因の特定と revert の下書きM4

6. フィードバックの輪（Kanflow に移す・W11）

図 4　フィードバックの輪。今は各エージェントモデルの手元（records.jsonl）にある記録と処理を、Kanflow のサーバーに移し、チームとプロジェクトをまたいで再発を防ぐ。
  • 確認済みの教訓だけを他のプロジェクトに返す（誤りを広げない）。機密の印のあるものは Claude に返さない。本文はデータで、指示ではない。
  • GitStation のエラーの目録（errors.toml）は正のまま。教訓は FG コードでリンクする。今ある mistake-memory は最初に取り込み、以後は廃止する。

11. 決めたこと（推奨案）

  • 共通部分の配り方: Claude Code のプラグインと社内のマーケットプレイス。最初は GitHub の非公開リポジトリ、GitStation ができたら移す。
  • 旧 Agent_Claudecode: 全体ができるまで今のまま使う（不具合の修正だけ）。その後 TMUX 版と Ver2 に切り替える。
  • CI: いまは GitHub Actions。GitStation の CI ができたら移す（オンプレの原則）。
  • 作業の宣言: セッションの開始で自動に宣言する。
  • フィードバックの輪: エージェントモデルではなく Kanflow のサーバーの機能にする。

  3. Kanflow: MariaDB での DB テストと E2E を CI で流す。
