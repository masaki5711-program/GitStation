## 目的

この規程は、品質マネジメントシステムで使う文書の作成・承認・発行・改訂・廃止の方法を定める。
目的は、使う場所で常に最新の承認済みの版が使われるようにすることである。

## 適用範囲

本社工場と第二工場で作る、[[QM-001]] の付表 1 に挙げた文書に適用する。
取引先から受け取る図面・仕様書（「外部文書」）は、この規程の 7. で扱う。

## 用語と定義

::: term T-01
文書: 業務の進め方や基準を定め、維持する情報。
規程・手順書・様式（雛形）を含む。
:::

::: term T-02
記録: 業務を行った結果を示し、保持する情報（記入済みの点検表など）。
記録はこの規程の対象の文書ではなく、[[QP-07-002]] で扱う。
:::

## 責任と権限

| 役割 | 作成 | 確認 | 承認 | 配布の管理 |
|---|---|---|---|---|
| 文書の owner のグループ | ○ | | | |
| 品質保証の担当 | | ○ | | ○ |
| 品質保証の責任者 | | | ○ | |

役割と GitStation のグループの対応は、リポジトリの設定で決める（個人の名前は書かない）。

## 手順

::: step S-1 role=作成者
文書番号は「QP-07-001」の形で、分類の番号と通し番号から付ける。
番号は一度付けたら変えない（廃止した番号も再利用しない）。
:::

::: step S-2 role=作成者
改訂の理由を MR の「改訂の理由」の欄に書き、確認を依頼する。

::: note
「軽微な訂正」（誤字・表記のゆれ）だけの改訂は、版を上げない。
数値・条件・手順の順番を変える改訂は、軽微にはできない。
:::
:::

::: step S-3 role="品質保証の担当"
内容を確認し、関係する文書（[[QP-07-001#T-01]] の定義に当たるもの）との矛盾が無いかを見る。
:::

::: step S-4 role="品質保証の責任者"
確認がそろったことを見て承認する。
承認は押印の代わりになり、承認の記録（氏名・日時・意味・中身のハッシュ）が残る。
:::

::: step S-5 role=作成者 status=deprecated
（旧）承認の後、紙に印刷して配布する。
:::
