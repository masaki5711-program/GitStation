## 4. 進め方の約束（利用者が決めたこと。必ず守る）

- **Kanflow は別のセッションで進める。このセッションでは Kanflow を実装せず、本番の `D:\APP\Kanflow`（:3000）には一切触れない。**
- **force push はしない。マイグレーションの編集やフックの迂回など契約に関わることは利用者に確認。全体のテストは同時に 1 本だけ。**
- 例外として承認済み: 未 push・未適用（使い捨てのテスト DB だけ）のマイグレーションの番号の付け替えや編集は、並行の MR との衝突を避けるためなら確認不要（報告だけ）。
- **自動マージは `full`**: 止めるのはプログラムの破壊（ビルドやテストが赤、大量削除）・DB の破壊・個人情報や秘密の流出だけ。「反映」は `main` へのマージまで。本番のデプロイは人間の承認。
- **トークンの節約**: 報告は短く日本語で。レビュー役は 1 MR に 2 人まで。簡単でテストのある修正は再レビューを省く。日常のエージェントは Sonnet。独立した MR は並行に。
- 実装エージェントは必ず別の worktree（`D:\APP\GitStation-wt-<topic>`）。`D:\APP\git_station\Git` を背景のエージェントから編集しない。
- マージの手順: `D:\APP\GitStation-main` で `git pull --ff-only origin main && git merge --no-ff --no-edit <branch> && git push origin main && git push gitlab main`。終わったら worktree とブランチを消す。
- コミットの作成者: `masaki.fujikawa@music.yamaha.com`。
- **リモート**: 製品は `origin` = GitHub `masaki5711-program/GitStation`、`gitlab` = 社内 GitLab `ymma/stragegic-planning/appications/gitstation`。マージのたびに両方へ push する。
