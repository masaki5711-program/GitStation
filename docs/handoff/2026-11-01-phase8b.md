## 3. MR8 の中身

- ルート（`app::member_routes`）: `GET|POST /api/v1/projects/{id}/members`、`PATCH|DELETE …/members/{user_id}`、同じものを
  `/api/v1/groups/{id}/members…`、`GET|POST /api/v1/projects/{id}/protected-refs`、`PATCH|DELETE …/protected-refs/{rule_id}`。
  `MemberManage` / `ProtectedRefManage` を `app::PLANNED` から外した。削除は `204`（`Registry::responds_no_content` を追加）。
- 新しい Action `MemberList`（プロジェクトは `ProjectRead` と同じ、グループはサインインした全員）と `ProtectedRefList`
  （`ProjectRead` と同じ）。どちらも `read_api`。メンバーの一覧はユーザー ID のキーセット（`limit` 1..=100、`after`）。
- 新しい文脈 `ProjectMemberCtx` / `GroupMemberCtx`（id = 対象とメンバーの組）、`RefProtectionCtx`（id = プロジェクトと規則の組）。
  変更の `from` はメンバーの**直接の**役割・規則のいまの水準で、ルートの読み込みとトランザクションの中で読む（依頼の値は使わない）。
  直接のメンバーでない人の変更・削除は `MembershipChange::Missing { to }`（Maintainer が必要）で判定し、その後 FG-REPO-0010
  `not_member`。存在しない規則は `from = to = None` で判定し、その後 FG-REPO-0005。読めない規則は Owner の水準。
- forge-db の新しいコマンド: `projects::{add,change,remove}_member_decided`、`groups::{add,change,remove}_member_decided`、
  `protected_refs::{create,change,delete}_decided`（MR7a の型: 対象 FOR UPDATE → 規則の行 FOR UPDATE → 呼び出し元の役割 FOR SHARE
  → アカウント → メンバーの行 FOR UPDATE → Owner が抜けるときは残る Owner のユーザー行 FOR SHARE → `decide` → 衝突と書き込み、
  `ChangeTx::settle`）。読み取り: `members::{page, one, direct_role}`、`protected_refs::{list, rule_state}`。
- 最後の Owner: `removes_last_owner` はトランザクションの中で計算し、`authorize()` が FG-AUTH-0003 `last_owner`（403）で拒否。
  forge-db の FG-REPO-0010 `last_owner` は予備の守り（`decide` が許しても書かない）。
- エージェント（`is_agent`）は `MemberManage` と `ProtectedRefManage` も拒否（FG-AUTH-0003 `reason=agent_token`、ADR-0017 / 0019
  の追記）。一覧は許す。
- 重複パターンは FG-REPO-0013（400）から **FG-REPO-0017 ProtectedRefPatternTaken（409）** へ（`duplicate_pattern` /
  `unique_index`）。FG-REPO-0015 は D5 の TransferInvalid のために空けたまま。イベントは既存の `member.*`（プロジェクトだけ、
  maintainer の分類）と `protected_ref.*` のまま。
- 権限表の行: 自分の昇格、最後の Owner の削除・降格、Maintainer のエージェント、Guest のメンバー一覧、保護より低い Developer、
  `read_api` / `api` / `write_repository` のトークン、無効なアカウント、削除待ちのプロジェクト（許可と拒否）。
- テスト: forge-auth（行列、エージェント、自分の昇格）、forge-db（`projects/tests/member_writes.rs`、`protected_refs/tests.rs`）、
  forge-hosting（`tests/members_protection.rs`、`tests/race.rs` に 2 件: メンバーの追加を待つ間に役割が消える、削除を待つ間に
  メンバーが Owner になる。`decided_callers` の対象を広げた）、forge-web（`tests/member_routes.rs`）。
- 範囲外として記録: 保護の削除と push の判定の同時実行（push は git の前に読んだ 1 つのスナップショットで判定する、ADR-0008）。
