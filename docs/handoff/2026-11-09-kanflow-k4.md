### GitStation: 不安定なテストの深掘り（2026-11-09 後半）

**訂正**: 先に書いた「DB の停止が原因の可能性が高い」は誤り。`a_killed_pack_refs_removes_its_own_lock_and_keeps_a_foreign_one` は
`2026-11-07-cloud-session.md` §7 の `a1420ad`（下限に 2 s の余裕）で既に直っていた（`2026-11-09-next-session.md` §2 の項目が古かった）。
今の main で単独 20 回・CPU と IO の負荷の下で 15 回、すべて合格。そのうえで、同じ箇所と同じ種類の不安定さを調べて、3 つ直した。

1. **殺した pack-refs のロックの窓の上限（本体の欠陥）**: `killed_at_unix_ms` をミリ秒に切り捨てていた。Linux 6.13 以降の multigrain
   timestamps では、ロックを誰か（doctor の `repositories.stale_locks`）が `stat` した後の書き込みの時刻は 1 ms より細かく、切り捨てた
   kill の時刻より後に見える（このコンテナで 2000 回中 1999 回。`stat` しない間は粗い時刻で 0 回）→ 自分のロックを残し誤った FG-GIT-0020。
   **修正**: 切り上げ（`command.rs` `ceil_millis`）。上限は kill を**送った**時刻のまま。kill の後に終了を確かめてから時刻を取る案は、
   独立レビュー 2 件（rust・git-protocol）の MEDIUM で退けた（確かめるまで 100 ms〜2 s、その間に他の書き手が取った生きたロックを消しうる）。
   遅い記憶装置で kill の後に書き終える git は、従来どおり残して名指す（安全側）。ADR-0024 Amendment 2026-11-09、runbook repo-maintenance。
   テスト: forge-git `a_lock_written_in_the_millisecond_of_the_kill_is_ours`（修正前 50 回中 48 回失敗）・`a_kill_time_is_carried_rounded_up_to_the_millisecond`、
   forge-cli `a_pack_refs_killed_while_writing_its_lock_removes_it`（1 ms ごとに `stat` する doctor 役つき。切り上げを外すと 6 回中 5 回失敗、付けると 10/10 合格）。
2. **時間切れの 0 の予算**（`2026-11-07-cloud-session.md` §8 と同じ種類の取り残し）: forge-git `push_scan::tests::a_size_check_that_cannot_finish_fails_closed`
   が `size_timeout = Duration::ZERO` で、負荷の下で速い `cat-file` が先に答えて検査が完了し（`incomplete: None`。本番の閉じ損ないではない）、
   forge-git のライブラリのテストを負荷の下で 5 回中 3 回落ちた → `test_git::stalled_git`（`--batch-all-objects` だけ止める）と `STALL` に。修正後 5/5 合格。
   forge-checks `real_browser.rs` の `reach_timeout: 1 ns` も同じ形（負荷の下で 12 回中 0 回で再現はしなかったが、forge-git の対の
   テストは既に直してある）→ `stalled_git(…, Some("rev-list"))`。残りの 0 / 1 ns（push_scan の全体の期限、spec_drift の `tokio::time::timeout`、
   merges の `grace`、purge の `run_budget`）は Rust の中で判定され確定的なのを読んで確かめ、変えていない。
3. **ETXTBSY（"Text file busy"）**: テストが偽の git・フックを `std::fs::write` してすぐ実行すると、並列のテストのスレッドが fork した子が
   書き込みのファイル記述子を exec まで持ち（O_CLOEXEC は exec で初めて閉じる）、実行が ETXTBSY で失敗する → forge は
   `GitUnavailable reason=spawn_failed`（`2026-11-07-cloud-session.md` §6 の `browse::history_tests … GitUnavailable` と、今回 1 回だけ落ちた
   `browse::tests::git_answers_forge_cannot_trust_are_git_process_failed` の l.890 がこの形）。6 スレッドが起動し続ける中で 7956 回中 1421 回起きた。
   **修正**: `forge_git::test_git::write_script`（子のプロセスの `sh -c 'cat > "$1" && chmod 755 "$1"'` で書く。テストのプロセスは
   書き込みで開かない）。14 か所（forge-git 9、forge-cli 4、forge-web 1）を置き換え、forge-web の dev-dependencies に forge-git の `test-support`。
   本番のフック（`install_push_hook`）は `forge serve` の起動時に 1 回書くだけで、push が実行するのはずっと後 → 影響なし。
   Windows は普通の書き込み（ETXTBSY は無い）。再レビュー（rust-reviewer）の HIGH「Windows の版が無くテストがコンパイルできない」を直し、
   `cargo check --target x86_64-pc-windows-gnu --tests -p forge-git -p forge-cli -p forge-checks` と forge-web の lib で確かめた（mingw を入れて）。
