## 2. 決めたこと（どれも ADR-0024 の「実装で決めたこと」に記録）

- **計画 11 §11 の決定 12**: マージの経路はサーバーのフックに頼らない。ロックの下で保護 ref の判定と先端の照合をやり直す。push の経路のフックは X8。
- **R4**: マージのジョブは worker でなく `forge serve` で動かす（閲覧のキャッシュを捨てるため）。
- **R5 のコミッターの規則は作り直した**。
  - 監査ログから到達をたどる方式はやめた。安い操作でリポジトリ全体の承認を止められる穴が続けて見つかったため。
  - push を受けるときに、受け取る前の全 ref の先端と比べて「その push が持ち込んだコミット」を `push_commits` に記録する。MR のコミッターは、範囲のコミットを push した人を 1 文で引く。
  - 行が無いコミットを範囲に持つ MR だけが `committers_unknown` で止まる。1 回の push の上限は 20,000 コミット。
- **R6**:
  - 必須チェックは C1 の `CheckResultsSource` まで報告が無いので、設定するとマージできない。設定時に警告を出し、runbook に脱出の手順がある。

  - 一時停止の期限は指定が必須で、延長はできない。
