**OIDC のクレート**: `openidconnect` は採らない。自前の薄いクライアント（`reqwest`）+ `jsonwebtoken` 11.1.0（`default-features = false`）+
forge-oidc の `ring` の `CryptoProvider`。理由: `openidconnect` 4.1.0 は `rsa` 0.9.10 を通常の依存に入れ、`cargo deny check advisories` が

ライブラリ（C のビルド）が入る。詳細と、jsonwebtoken の provider がないときの `panic!` の閉じ方は ADR-0021 §15。

## 3. 計画 10 とコード・文書の食い違い（ADR で決めたもの）

1. **`__Host-gstn_oidc` の `Path=/-/auth/`** は不可（`__Host-` は `Path=/` が必須）。`Path=/` にした（ADR-0021 §3）。
2. **ロゴの置き場所**: 計画 10 §0 は「`docs/overview/` にしかない」としたが、`docs/brand/`（v1 の SVG と色の表、ユーザーの指示
   2026-10-30「必ずこのフォルダを使う」）がある。正は `docs/brand/`。`docs/overview/*.png` の色を測り、README の値と一致することを確かめた（ADR-0022）。
3. **`web.base_url` が未実装**: ADR-0015 が参照しているが、設定に `web.*` / `auth.*` の名前空間がない（墓標の 302 は相対パス）。
   ADR-0021 §12 で足す（`FORGE_WEB_`、`FORGE_AUTH_`）。`Origin` の検査の前提なので MR3 で入れる。
4. **`id_token_hint`** に ID トークンが要るが、計画の `web_sessions` の列にない。`id_token_enc` を足した（ADR-0021 §5）。
5. **同時のリフレッシュ**: Keycloak の「Revoke Refresh Token」が有効だと、同時の 2 回の片方が `invalid_grant` になり、正しいセッションを
   `idp_revoked` で切る。1 セッション 1 回だけにする条件付きの UPDATE を決めた（ADR-0021 §7）。
6. **社員番号の claim がないとき**の扱いが計画にない。必須にした（mapper の誤りで既存の全員の重複を作らない。FG-AUTH-0014
   `employee_number_missing`）。
7. **`auth.oidc` がないとき**のコードを FG-SYS-0002 にすると 500・alert になる。新しい **FG-AUTH-0018 LoginNotConfigured**（503、info）を予定に足した。
8. **`users.auth_source`**（CHECK `local`|`ldap`）は変えない計画なので、OIDC で作る利用者は `local` になる。列はもうログインの方式を表さない
   と ADR-0021 §4 に書いた（整理は見送り）。計画 09 §8.2 の「利用者の表に外部の ID」は別の表 `user_identities` で満たす。
9. **`access` のロール**は ID トークンから読む（アクセストークンを使わないため）。Keycloak の client に、クライアントロールを ID トークンに
   入れる mapper が要る（ADR-0021 §13 の求める形に入れた）。
10. **計画 09 §8.5「Keycloak で無効にした人は次の操作から入れない」**: リフレッシュの確認は 5 分ごとなので、バックチャネルのログアウトが
    来ないときは最大 5 分遅れる。受け入れるリスクとして ADR-0021 §7 に書いた。
11. **`rust-version`**: workspace は 1.85 だが、`jsonwebtoken` 10 / 11（と `openidconnect` 4.1）は 1.88 を要する。MR4 で上げる
    （ツールチェーンは 1.99.1 なので作れる）。
12. **`/-/assets` と ADR-0015 の「`/assets/…` か `/-/static/…`」**: `/-/assets/` に決め、元の文を置き換えた（ADR-0015 の Amendment M2）。
13. 計画 10 §5 の `GET /api/v1/user/sessions` が Action `SessionRevoke` になっている（一覧に失効の Action）。→ レビューの 5 で
    `SessionList` と `Resource::Session { owner }` に決めた（ADR-0021 §17）。計画 10 の `POST /api/v1/session/logout` も
    `POST /-/auth/logout` に変えた（レビューの 10）。
14. `cargo audit` はこのリポジトリの `.cargo/audit.toml` の無視（`sqlx-mysql` の名残の `rsa`）が効くので、`rsa` を実際に入れても
    何も言わない。依存の判断は `cargo deny` の結果で行う（ADR-0021 §15）。

## 6. 利用者に確かめてほしいこと

- Keycloak の準備の依頼（ADR-0021 §13 の形）を IoT プラットフォームの担当へ渡すこと。とくに ID トークンへのクライアントロールの mapper と、
