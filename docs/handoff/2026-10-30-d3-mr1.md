## 2. MR1 でやったこと

- forge-core: `Scope` を forge-auth から移動（`parse` / `ALL` 追加、forge-auth は再公開）。`token.rs`（`fgp_<16 hex>_<64 hex>`、
  getrandom 256 bit、SHA-256、subtle の定数時間比較、秘密の型は `Serialize` / `Display` / `==` なし）。
  `AuditDetails::{TokenCreated, TokenRevoked}`、`UserDisabled` に `revoked_tokens`。
- forge-db: マイグレーション `20261030100000_tokens.sql`（`is_agent` 列あり、`forge_ro` はハッシュを読めない、DELETE なし）、
  `tokens::{issue, revoke, list, authenticate}`（`crates/forge-db/src/tokens/`）、`users::id_by_username`、
  `users::disable` が有効なトークンを同じ変更で一括失効（`revoked_reason='user_disabled'`、トークンごとに `token.revoked`）。
- `authenticate` は無効化された所有者のトークンを自分で `FG-AUTH-0004 reason=owner_disabled` にする（呼び出し側の確認漏れを防ぐ）。
- forge-cli: `forge admin token issue | revoke | list`（`crates/forge-cli/src/admin_token.rs`）。トークンは標準出力に 1 回だけ、ログには出さない。
- エラーコード: FG-AUTH-0008 TokenRequestInvalid、FG-DB-0019 CredentialDataInvalid（Runbook `ops/runbooks/credential-data.md`）。
- ADR-0019 を新規。ADR-0010 / 0016 / 0017 / 0018 に Amendment。ADR-0017 には自動マージの 4 方式と危険の検査（F）も追記。
- 独立レビュー 2 ラウンド（7 評価者）: CRITICAL / HIGH なし。admin スコープの判定を forge-db に置く件は、ユーザーの決定で
  「CLI の経路だけの明示的な例外」（ADR-0019 §8）。
