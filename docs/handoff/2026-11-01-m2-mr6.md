## 3. 計画・ADR との違い（決めたこと）

1. `Resource::Session` に `route` を足した（ADR-0021 §17 は `{ owner }` だけ）。利用者のルートでは管理者でも他人のセッションは 404。
2. 利用者のルートのセッションの指定は数字の id ではなく `public_id`。
3. `TokenRevoke` は今の表のまま、管理者は利用者のルートでも他人のトークンを失効できる（計画 10 §5 の「deny: 他人」は管理者以外）。
4. gstn に `token create` はない（サーバーがトークンでの作成を断るため）。
5. グループの一覧にも `membership=true` を足した。
6. 利用者のルートの DELETE で、トークンの呼び出し元は「ない `public_id`」が 404、「ある `public_id`」が 403 になる（受け入れた。ADR-0021 の 31）。
7. アカウントの書き込みは判定 1 回（持ち主は変わらない、DB 側の守りあり）。管理者自身の権利の読み直しはしていない（ADR-0019 MR6 の 3）。
