## 3. ADR・計画との違い（決めたこと）

1. 設定の名前は `web.session_idle_secs` / `web.session_absolute_secs`（ADR-0021 §12 は `web.session_idle` / `web.session_absolute`）。ほかのキー（`hosting.purge_interval_secs`）にそろえて単位を名前に入れた。
2. `web.base_url` は読み込みでは任意、`forge serve` が必須にする（`forge doctor` や CLI のコマンドを止めないため）。値は https か http の localhost / 127.0.0.1 / [::1] だけ、パス・クエリ・利用者の情報なし。
3. `SessionList` / `SessionRevoke` と `Resource::Session { owner }` は入れていない（ADR-0021 §17 と MR1 の引き継ぎの通り、ルートと一緒に MR6）。MR3 は `SessionRead` だけ。
4. 失効の順: 無効の利用者のセッションは `session_revoked` ではなく **FG-AUTH-0004**（ADR-0019 Amendment M2 の「次の要求は FG-AUTH-0004」）。照合は利用者の状態を失効より先に見る（トークンは失効が先のまま）。
5. FG-AUTH-0001 のセッションの reason は `session_malformed` / `session_unknown` / `session_mismatch` も足した（ADR は expired / revoked だけ）。
6. CSRF の検査 2 は API と raw・archive に掛ける。**git Smart HTTP の POST は検査 1 だけ**（git は Basic で push し、CSRF のトークンを持たない。ブラウザからの偽の POST は Origin があるので検査 1 で止まる）。raw・archive の Basic の状態を変える要求は `token_missing`（そういうルートは今ない）。
7. 一括の失効の監査は新しい action `session.revoked_all`（`details.revoked_sessions`）。ADR は `session.created` / `session.revoked` だけを書いている。
8. `web_sessions` の DELETE（期限から 30 日後の掃除）は、ジョブを入れる MR で権限と一緒に足す（この MR では付けない）。
9. セッションで認証した書き込みの `ChangeContext.credential_id` は今は入れない（列はトークンの id。セッションの id をどう区別して残すかは MR4 / MR6 で決める）。

- `FORGE_TEST_DATABASE_URL=postgres://forge_dev@127.0.0.1:55432/forge_dev CARGO_TARGET_DIR=… CARGO_INCREMENTAL=0 cargo nextest run --no-fail-fast -p forge-db -p forge-auth -p forge-web -p forge-cli -p forge-hosting -p forge-core -p forge-client -j 2`

  もう一度流した → 39 件すべて通過。
