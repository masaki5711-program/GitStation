## 2. 入れたもの（コミット順）

1. `refactor(git): split browse.rs into browse/{path,refs,tree,content}` — **移動だけ**（`pub(super)` と import 以外の変更なし）。テストは `browse/tests.rs`。公開パス（`forge_git::browse::…`）は再 export で不変。
2. `feat(git): browse history` — forge-git:
   - `commits(repo, tip, path, limit, after)`: `log -z --format=… -n N [--skip K] --end-of-options <tip> [-- path]`、区切りは `0x1f`。`LogCursor { tip, last, skip }`（`v1.<tip>.<last>.<skip>`）は**カーソルの起点から**読み直し、先頭の 1 件が `last` であることを確かめて捨てる（合わなければ `cursor_invalid rule=anchor`）。起点が commit でなければ `FG-REPO-0023`。
   - `commit(repo, oid)`: `log -1` の本文 + 最初の親との差分（ルートは `--root`）。`compare(repo, from, to)`: `log to ^from`（200 件まで）+ 2 本の木の差分、20 秒。
   - `Diff`（`diff.rs`）: `diff-tree --raw -z --no-abbrev`（ファイルの一覧、500 まで）と `-p`（パッチ合計 2 MiB で git を止める）を別々に走らせ、`diff --git ` の行で分けて順番に対応させる（型の変更は 2 つ）。数が合わなければ `FG-GIT-0003 reason=diff_chunk_mismatch`。パッチは全部か無いかで、無いときは `PatchOmitted::{TooLarge(256 KiB 超), TotalCap, NotUtf8}`。バイナリは `binary` で `patch` なし。
   - `blame`（`blame.rs`）: `blame --porcelain -L 1,<上限+1> <id> -- <path>`、10 000 行まで `truncated`、NUL / 非 UTF-8 の行があれば `binary`（行なし）、空ファイルは空、20 秒。**git の blame は `--end-of-options` を受け付けない**ので、検証済みの 16 進数の ID を `--` の前の唯一の引数にした。
   - `BrowseLimits` に `blame_timeout`・`compare_timeout`・`max_log_page`・`max_log_skip`・`max_compare_commits`・`max_diff_files`・`max_diff_bytes`・`max_file_patch_bytes`・`max_blame_lines`。`Revision::excluding()`（`^<id>`）。1 回の git 呼び出しごとにリポジトリの枠を 1 つ取る点は MR7 と同じ。
3. `feat(web): history browse API` — `routes/history.rs`: `GET …/repository/{commits,commits/{oid},compare,blame}`（`RepoBrowse`、`read_api`）。`commits/{oid}` 用のローダー `CommitOf` と `Dispatched::raw_path()`（oid は `authorize()` の後で検証）。`routes/browse.rs` の補助関数を `pub(crate)` にして共有。`dispatch_tests` の forge-git 利用許可に `routes/history.rs` を追加。`errors.toml` の FG-REPO-0023・FG-WEB-0006・FG-GIT-0003 の説明を拡張、カタログ・`openapi.json`・`routes.generated.json` を再生成。
4. `feat(client): gstn browse commits, commit, compare, blame` — `--patch`（commit・compare）。**パスに入る唯一の値**である commit ID は clap が 40 / 64 桁の 16 進数だけを通す（小文字にする）。ref・パス・カーソルは query の値。サーバーの文字（本文・名前・パッチ・blame の行）は端末向けに無害化。`coverage.rs` に 4 行、`help --json` のスナップショットを更新。
5. 文書（このコミット）: ADR-0015 の「M2 MR8」Amendment、forge-git・forge-web の README、この引き継ぎ。

## 3. 計画・ADR との違い（決めたこと）

詳細は ADR-0015 の「M2 MR8」の表。要点:

1. キーセットのカーソルは「最後のコミット ID」を鍵にしつつ、読み直しの手段として件数を持つ（git の log に真のキー検索がないため）。署名はしない。
2. マージコミットの差分は最初の親との差分。比較は 2 ドット（merge-base なし）。
3. 新しいエラーコードは足していない（`reason` を目録に追記）。
4. コミットの名前・件名・本文は UTF-8 の置き換え文字を許す（表示用）。ID の形が壊れた記録だけは `FG-GIT-0003`（`log_record_*`）。

## 6. 次（MR9 以降への宿題・見送り）

- 木の項目名が UTF-8 でないものの扱い（MR7 から継続）。
- 3 ドットの比較（merge-base）が画面で要るかは MR10 で決める。
- `commits` の `--follow` 相当（名前の変更をまたぐ履歴）は入れていない。
- `git.browse.*` の設定は足していない（既定値のみ）。
- 差分の行数の統計（追加・削除の行数）は返していない。画面で要るなら `--numstat` を足す。
- 深いカーソル（`--skip`）は 1 ページごとに先頭から数え直すので、全ページを読むと O(n²)。`max_log_skip` 100 000 と 10 秒の期限で抑えている（LOW、受け入れ）。
