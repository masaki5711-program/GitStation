## 3. 計画・ADR との違い（決めたこと）

1. **上限を超える木とファイルはエラーにせず切り詰める**（`truncated: true`）。計画は「上限を超える木とファイル」をテストに挙げるだけで扱いを決めていなかった。新しいエラーコードは足していない。
2. raw の型の判定は **4 MiB 以下だけ**。それより大きいものは画像でもダウンロード（stream の先頭を覗かない）。
3. ダウンロードだけにする拡張子を SVG・HTML・PDF から XML・XSL・MHT の系統まで広げた。
4. リポジトリごとの同時実行の上限は取り込みの呼び出しだけ。archive と大きい raw は既存の stream の上限（全体 16、利用者ごと 4）で抑える。
5. `?ref=` の 16 進数は大文字も受け付けて小文字にする。16 進数はコミットとしてだけ扱い、存在しなければ同じ名前のブランチに落とさず `ref_not_found`。
6. 閲覧の設定（`git.browse.*`）は足していない。既定値（`BrowseLimits::default()`）だけ。
7. archive の中のディレクトリは `<プロジェクト>-<コミット 12 桁>/`（ref の名前は入れない）。

## 7. レビュー（`e72b4c6`）と 2 つ目のコミット

security: 指摘なし。authz・git-protocol: CRITICAL / HIGH なし。rust: HIGH 1。2 つ目のコミットで直したもの:

- **HIGH** `parse_tree` が読めない記録（タブなし、欄の不足、知らない型）を黙って捨てていた → 数えて、1 回の warn `forge.git.browse.tree_entries_skipped`（`repo_id`、`error_code=FG-GIT-0003`、`malformed`、`not_utf8`）。
- 木の項目名が UTF-8 でないものは置き換えの文字で見せず、数えて外す（同じ warn）。
- `entry_at` の出力が上限で切れたら 404 にせず `FG-GIT-0003 reason=ls_tree_truncated`。
- blob の大きさがない項目は `FG-GIT-0003 reason=blob_size_missing`（`TreeEntry::blob_size`。`unwrap_or(0)` をやめた）。id の確認が何も返さないときは `reason=batch_check_empty`。
- push: receive-pack の出力が閉じた時点（最後の応答を送る前）で ref のキャッシュを消す。drop の守りは残す。
- テスト: `output_truncated`、`blob_size_mismatch`・`tree_of_commit_unreadable`・`batch_check_empty`・`ls_tree_truncated`（偽の git）、壊れた `ls-tree` の出力、UTF-8 でない名前。raw・archive の GET と HEAD で匿名・Guest・削除待ち・internal・非メンバー・`read_api` のトークン。閲覧の API の 4 つのルートすべてで拒否の表。権限の表に `NonMemberTokenReadApi`・`GuestTokenReadApi` の行（private で拒否、internal で許可）。
- archive の prefix: プロジェクトの名前の段は `PathSegment::parse` で常に小文字（コメントに書いた）。

見送り（LOW）: raw の HEAD は 4 MiB 以下なら中身を読む（型の判定に要る。読まずに済ませるなら HEAD は型を返せない）。archive のリポジトリごとの stream の上限は作らず、既存の stream の上限だけ（ADR-0015 の MR7 の Amendment に記載）。`browse.rs` の分割は MR8。
