# Runbook: internal-error（FG-SYS-0001）

## Trigger

- ログに `error_code=FG-SYS-0001` が出た
- 利用者から「内部エラー」と問い合わせ番号の連絡があった

## Impact

単発なら 1 リクエストの失敗。継続して出る場合は、特定の機能が使えない状態。
**このコードが出ること自体が、エラー台帳の抜け（より具体的なコードがない）を意味する。**

## Diagnose（読み取りのみ）

1. 問い合わせ番号（`request_id`）でログを絞り込む:
   `forge diag bundle` の出力、またはログファイルから `request_id=<番号>` の行を抽出する。
2. `context` と `source` フィールド、span の連鎖から、発生したクレートと操作を特定する。
3. 同じ `context` の発生件数と時間帯を数える（単発か、継続か）。
4. 直近のデプロイ・設定変更・マイグレーションとの時刻の一致を確認する（`git -C Git log --since`）。

## Mitigate

1. 継続して出ていて直前にリリースがある場合: 1 つ前のリリースへ戻すことを検討する。
   `[MUTATING — needs approval]`（ロールバック: 再度最新リリースへ戻す）
2. 単発の場合: 緩和は不要。Diagnose の結果を障害記録に残す。

## Verify

`error_code=FG-SYS-0001` の新規発生が止まったこと。利用者の操作が再現しないこと。

## Escalate

- データの破損・漏洩の疑いがある → SEV1 として `/incident`。
- 原因箇所が特定できたら、**具体的なエラーコードを新設**するフィードバックアクションを起票する（`error-contract` スキル）。
